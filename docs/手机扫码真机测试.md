# 手机扫码真机测试指南

> 目标：用手机微信扫描开发者工具生成的二维码，在真机上跑通这个小程序。

---

## 零、先跑一次自检

```bash
node tools/doctor.js
```

8 项检查全绿 = 环境就绪。当前状态：**只剩 AppID 一项待处理**（见第二节）。

---

## 一、先说结论：三步走

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| **1** | 换掉 `touristappid`，填你自己的小程序 AppID | 游客模式**禁用「预览」**，点不了二维码 |
| **2** | 把小程序地址改成电脑局域网 IP（已帮你改好） | 手机上的 `127.0.0.1` 指的是手机自己，连不到你的电脑 |
| **3** | 手机和电脑连同一个 WiFi，点「预览」扫码 | 真机必须在同一局域网 |

---

## 二、第一步：换 AppID（必须做）

当前 `project.config.json` 里是：

```json
"appid": "touristappid"
```

**游客模式（touristappid）的限制**：工具栏的「预览」「真机调试」两个按钮是灰的 / 点了报错。
→ 必须换成真实 AppID 才能扫码。

**获取 AppID（免费，5 分钟）**：

1. 打开 https://mp.weixin.qq.com/ → 右上角「立即注册」→ 选「小程序」
2. 用一个没注册过公众平台的邮箱注册，按提示完成（个人主体就行，不需要企业认证）
3. 登录后：**开发 → 开发管理 → 开发设置**，页面上能看到 **AppID(小程序ID)**，复制它
4. 打开 `project.config.json`，把 `"touristappid"` 换成你的 AppID

也可以不改文件——开发者工具右上角「详情 → 基本信息 → AppID」直接改，工具会自动写回配置文件。

> 换成真实 AppID 后，开发阶段仍需在「详情 → 本地设置」勾选 **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**，否则 `http://` 请求会被拦。

---

## 三、第二步：改小程序后端地址（已自动改好）

我已经帮你把地址切到真机模式了：

```js
// miniprogram/utils/constants.js
const API_BASE_URL = 'http://192.168.31.74:3000';
```

`192.168.31.74` 是你电脑当前的局域网 IP。

**以后换网络 / 换 WiFi 后 IP 会变，用这个命令一键重新适配：**

```bash
# 查看当前 IP 和地址状态
node tools/lan-ip.js

# 自动切到真机模式（用检测到的第一个局域网 IP）
node tools/lan-ip.js --set

# 切回模拟器模式（开发者工具里调试时用）
node tools/lan-ip.js --local
```

> 开发工具里的模拟器用 `127.0.0.1`，手机真机用 `192.168.x.x` —— 两者互斥，切换时记得用上面的命令。

---

## 四、第三步：放行防火墙（已帮你做好）

Windows 防火墙默认**拦截**外部设备访问 3000 端口，这是"手机连不上"的头号原因。

我已添加放行规则：

```
规则名称: WC-Backend-3000
方向: 入   协议: TCP   本地端口: 3000   操作: 允许
配置文件: 域,专用,公用   （三个都放行）
```

如果以后重装系统或换电脑，用这条命令重建（**需管理员权限**）：

```powershell
netsh advfirewall firewall add rule name="WC-Backend-3000" dir=in action=allow protocol=TCP localport=3000
```

删除规则：

```powershell
netsh advfirewall firewall delete rule name="WC-Backend-3000"
```

## 五、第四步：启动后端 → 扫码

**1. 确认后端在跑**（在 `server/` 目录）：

```bash
cd server
npm start
```

启动后会看到这样的输出，其中就有真机要用的地址：

```
✓ 服务已启动: http://localhost:3000
  管理后台  : http://localhost:3000/admin/

  ┌───────────── 手机真机测试（局域网）─────────────┐
  │  后端地址：http://192.168.31.74:3000
  │  后台地址：http://192.168.31.74:3000/admin/
  │  ↑ 把这些地址填到 miniprogram/utils/constants.js
  │  手机和电脑必须连同一个 WiFi
  └────────────────────────────────────────────────┘
```

**2. 先用电脑浏览器验证**：

打开 `http://192.168.31.74:3000/healthz`，看到 `{"ok":true,...}` 说明局域网可达。

**3. 再点「预览」**：

开发者工具顶部工具栏 →「预览」→ 生成二维码 → 手机微信扫一扫。

**4. 手机上打开调试**：

扫码进入后，点右上角「…」→「打开调试」，能看到 console 日志。如果报错，这里看得到真实原因。

## 六、常见问题速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 「预览」按钮是灰的 | 用的 `touristappid` | 换真实 AppID（见第二步） |
| 手机扫码后白屏 / 一直转圈 | 手机连不到后端 | ① 确认同一 WiFi ② 确认防火墙放行 ③ 浏览器测 `/healthz` |
| 提示 `url not in domain list` | 「不校验合法域名」没勾 | 详情 → 本地设置 → 勾选「不校验合法域名…」 |
| 提示 `网络异常：...` | 地址不对或后端没起 | 用 `node tools/lan-ip.js` 核对 IP；确认 `npm start` 在跑 |
| 电脑浏览器能开，手机不能 | 防火墙 / 不同网段 | 手机浏览器直接访问 `http://192.168.31.74:3000/healthz` 测一下 |
| 电脑有多个网卡，IP 选错 | VMware/虚拟网卡干扰 | 用 `node tools/lan-ip.js`，它已自动排除虚拟网卡，优先 192.168 |

## 七、真机 vs 模拟器，差异提醒

| 能力 | 模拟器 | 真机 |
|---|---|---|
| 访问 `127.0.0.1` | ✅ 通 | ❌ 指向手机自己 |
| 相册选图 / 拍照 | ⚠️ 用电脑文件代替 | ✅ 真实相册 |
| 保存到相册 | ❌ 不支持 | ✅ 真实写入 |
| 视频处理性能 | 快（电脑 CPU） | 慢（手机 CPU），大视频可能超时 |
| 网络请求 | 走电脑网络 | 走手机网络 |

> 涉及**相册保存、相机、真实性能**的功能，必须真机测。纯逻辑和 UI 用模拟器就够了。

## 八、配套工具速查

项目 `tools/` 目录下有三个脚本，全部零依赖、跨平台：

| 命令 | 作用 |
|---|---|
| `node tools/doctor.js` | **环境自检**：Node / MySQL / 数据表 / FFmpeg / 端口 / 小程序地址 / AppID 共 8 项，给出修复建议 |
| `node tools/lan-ip.js` | 查看本机局域网 IP 与当前小程序地址 |
| `node tools/lan-ip.js --set` | 一键切真机模式（自动写入局域网 IP） |
| `node tools/lan-ip.js --local` | 切回模拟器模式（`127.0.0.1`） |
| `node tools/lan-ip.js --firewall` | 打印放行 3000 端口的命令 |
| `node tools/smoke-test.js` | **接口冒烟测试**：44 项覆盖小程序端全部调用 + 后台，全绿说明前后端对齐无误 |
| `node tools/get-ffmpeg.js` | 下载安装 FFmpeg 到 `tools/bin/`（视频功能依赖，已内置，换机器时用） |
| `node tools/get-ffmpeg.js --check` | 只检测 FFmpeg 是否可用 |

**推荐工作流**：

```bash
# 每次开始开发前
node tools/doctor.js

# 改完后端接口后，验证对齐
node tools/smoke-test.js

# 要上真机测试
node tools/lan-ip.js --set
cd server && npm start        # 看启动日志里的局域网地址
# → 开发者工具点「预览」→ 扫码

# 回到模拟器调试
node tools/lan-ip.js --local
```
